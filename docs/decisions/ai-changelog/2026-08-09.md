## fix(agentcore): 输出完整性链路修复：纯文本 max_tokens 截断自动续写 + FinishReason 全通道透传

背景：审查智能体输入→输出链条发现，纯文本输出被 max_tokens 截断（finish_reason=\length\）时被当作正常完成，且仅 TUI 通道对截断有用户提示，Server/ACP/Desktop 通道完全无感知，客户端拿到不完整输出却不知情。

改动清单：
1. agentcore（根因）：runInnerLoop 无工具调用分支检测 finish_reason=\length\，自动注入 steering 消息要求模型从断点续写一次（maxTruncationContinuations=1，受 MaxTurns 约束），续写后仍截断则保留 finish_reason=\length\ 正常结束，避免无限循环；新增 Agent.LastFinishReason() 供同步调用方读取最近结束原因。
2. server：AgentEndStreamPayload / StreamDoneEvent / ChatResponse 均新增 finish_reason 字段，SSE 流与同步端点透传截断/异常信号。
3. agui + desktop：RunFinishedEvent 新增 finishReason 字段（RunFinishedWithSuccess 可变参数向后兼容）；desktop 前端订阅 agui:run-finished，finishReason=length/error 时在聊天视图展示\输出可能不完整\提示（新轮次开始自动清除）。
4. acp：PromptResponse 新增 finishReason 字段，handlePrompt 通过 Agent.LastFinishReason() 透传。

验证：agentcore 新增 3 个续写测试（自动续写/续写耗尽/steering 持久化），server/agui/acp/前端各新增透传回归测试；根模块 go vet + go test + 受影响包 -race + golangci-lint 全过，tui/desktop（Go+前端 typecheck/test/lint）全过，make verify 通过。

影响：向后兼容——所有新增字段 omitempty/可选参数，不破坏既有客户端；行为变化仅限截断场景（自动续写一次 + 多通道透传提示）。
