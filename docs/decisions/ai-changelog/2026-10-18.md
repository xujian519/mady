## fix(domains): P0 修复：SQLite 时间列格式统一、审计参数扫描越界、工具入参静默吞错

**背景**：M14/M15 日卡（docs/code-review-plan.md）登记 7 项 P0。本卡优先修复影响面最大的 4 项，全部为行为修复并带回归用例。

**改动清单**：
- `domains/sqlite`、`domains/caseindex`：新增 `timefmt.go`（写入 UTC RFC3339 + 读取兼容历史格式），建表默认值改 `strftime`，`ExpirePending`/`Prune`/排序全部经 `datetime()` 归一化并加主键兜底
- `domains/audit_extension.go`：`extractArgNames` 补越界退出；`truncateAuditDetail` 改为 UTF-8 边界回退
- `domains/case_ext_list.go`、`domains/case_ext_sync.go`：区分空参数与非法参数，后者返回错误结果
- 新增 3 个测试文件（sqlite/caseindex 时间列、审计辅助函数）

**1. 时间列双格式（影响最大）**
`domains/sqlite` 与 `domains/caseindex` 的建表默认值 `datetime('now')`（`YYYY-MM-DD HH:MM:SS`，无时区）与 Go 侧写入的 RFC3339 混用。三处后果：① `expires_at < datetime('now')` 是字符串比较，RFC3339 的 `T`(0x54) 大于空格的 ` `，同一天到期的审批请求要等到次日才被标记过期（`cmd/mady/tui_session_storage.go` 每 5 分钟调用）；② `Prune` 反向同理，会把同一天的历史事件误判为更早而删除；③ 读取侧按 RFC3339 解析失败，`case_paths.created_at`/`case_events.event_date`/`responded_at` 恒为零值，`checkpoint_store.LoadLatest` 更把 TEXT 列直接 Scan 到 `time.Time`。
修复方式：写入侧显式提供 UTC RFC3339，建表默认值改为 `strftime('%Y-%m-%dT%H:%M:%SZ','now')`；读取侧新增 `parseTimeText` 兼容历史文本；比较与排序一律经 `datetime()` 归一化并追加主键/rowid 兜底（避免同秒并列次序不确定）。

**2. `audit_extension.extractArgNames` 越界 panic**
未闭合引号的 JSON 参数使内层扫描走到末尾后执行 `raw[j+1:]`，切片越界 panic；`AfterToolExecution` 无 recover，一次畸形工具参数即可打断整个 Agent 运行。补 `j >= len(raw)` 提前退出。

**3. `truncateAuditDetail` 产出非法 UTF-8**
`detail[:497]` 按字节切会把中文截成半个字符。改为回退到最近的 UTF-8 字符边界。

**4. `case_ext_list`/`case_ext_sync` 静默吞入参错误**
`_ = json.Unmarshal(args, &input)` 后按零值查询：模型把 `year` 写成字符串时会静默返回全部案件；`sync_case` 非法参数则静默改扫 cwd。改为区分「空参数=不过滤」与「非法参数=返回错误结果」。

**提交**：`3013ec0`（时间列，14 文件）、`eb427ae`（审计与入参，4 文件）
