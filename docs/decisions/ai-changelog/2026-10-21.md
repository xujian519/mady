## fix(knowledge/fileindex): 修复大文件截断 panic 与 .xls stat 空指针

**背景**：M16 日卡复现两个 P0。readText 的截断预算按字节（1MB）声明，执行却用 `[]rune[:1MB]` 切片，中文文件约 33 万 rune 时越界 panic（400k 汉字探针复现 `slice bounds out of range [:1000000] with capacity 401408`）；readSpreadsheet 的 .xls 分支忽略 `os.Stat` 错误后解引用 `info.Size()`，文件被删除即 SIGSEGV。

**改动清单**：
- `knowledge/fileindex/reader_text.go`：截断改按字节预算并回退到 UTF-8 边界（`utf8.RuneStart`），保留截断提示文案。
- `knowledge/fileindex/reader_spreadsheet.go`：`os.Stat` 失败时返回错误，不再解引用空 `info`。
- `knowledge/fileindex/reader_test.go`：新增大体积多字节文本截断用例与缺失 .xls 文件用例。

**验证**：`go test -race ./knowledge/...` 全绿；两个探针修复后均正常返回。

**影响**：仅影响超限文本截断与异常文件路径，正常读取行为不变。

## fix(memory): 会话汇总空 facts 响应不再产出伪事实

**背景**：M17 日卡发现 `parseSummaryResponse` 在 LLM 合法返回 `{"facts": []}` 时，JSON 解析成功但事实列表为空，随后仍走逐行 fallback，把整段 JSON 文本存入长期记忆。探针：输入 `{"facts": []}` → 返回 1 条内容为 `{"facts": []}` 的事实。

**改动清单**：
- `memory/session_summarizer.go`：JSON 解析成功且 facts 为空时直接返回 nil；仅解析失败才降级逐行解析。
- `memory/session_summarizer_test.go`：新增 `TestParseSummaryResponse_EmptyFacts` 与 `TestParseSummaryResponse_PlainTextFallback`。

**验证**：`go test ./memory -run TestParseSummaryResponse` 通过。

**影响**：空结果不再写入垃圾记忆；纯文本响应仍按原逻辑提取。

## fix(memory): 事实前缀剥离保留行首数字

**背景**：M17 日卡发现 `parseFactsFromText`/`parseFactsFromLines` 用 `strings.TrimLeft` 按字符集削前缀，正文开头的数字会被当作列表编号剥离：`2026年用户代理了10件专利` 变成 `年用户代理了10件专利`，事实内容失真。

- `memory/extractor_llm_test.go`：新增 `TestParseFactsFromText_PreservesLeadingDigits`。

**验证**：`go test ./memory -run TestParseFacts` 通过。

**影响**：编号/项目符号剥离行为不变；数字开头的事实不再丢失首字。
