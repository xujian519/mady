## fix(tui): 修复 overlay 关闭后界面残留/空白

**背景**：打开并关闭 /help、/settings、Ctrl+P、Ctrl+T 后，被 overlay 覆盖的区域会残留旧文字或变成空白，只有窗口 resize 触发的全量重绘才能恢复。

**根因**：renderChildrenRows 的行级缓存以“合成前的基础行字符串”为 key，却复用“合成后”的行。overlay 打开后的下一帧把 overlay 像素缓存成基础行；关闭时 DiffFrame 认为基础行没变，旧像素永久留在终端。

**改动清单**：
- overlay 存在期间禁用行级缓存复用，且不把合成行写入 prevRaw
- PushOverlay / PopOverlay / RemoveOverlay 调用 invalidateFrameCache，强制下一帧全量重绘
- 新增 TestOverlayCloseRepaintsBaseFrame：先复现残留（diff 输出为空），修复后断言被覆盖基础行被重绘、第二帧稳定

**验证**：cd tui && go test -count=1 ./...、go test -race -count=1 ./...、golangci-lint run ./... 通过；tmux 实测 /help、/settings、Ctrl+P、Ctrl+T 关闭后均恢复全宽界面。

**影响**：仅 overlay 开合期间多一次全量重绘，常规帧渲染路径不变。

## fix(tui): chat overlay 默认居中显示

**背景**：/help、/settings、命令面板、任务面板等所有 chat overlay 都贴右下角。

**根因**：tuiAppHost.PushOverlay 把 PercentX/Y=50 连同零值 AnchorTopLeft 一起传入，resolveOverlayOrigin 将 50% 解释为“左上角位置”，再被 clamp 到 cols-w / rows-h，最终稳定停在右下角。

**改动清单**：
- chat 层未显式指定锚点时（overlayHandle 恒为 0）在桥接层改为 AnchorCenter
- 新增 TestTuiAppHostCentersOverlayByDefault：120x40、70% 面板断言 anchor 与渲染原点 (row=6,col=18)

**验证**：go test -race ./...、golangci-lint run ./... 通过；tmux 120x40 实测 /settings 左上角 (10,24)、/help 左上角 (6,18)，与居中公式一致。

**影响**：所有模态面板居中；鼠标坐标平移继续使用 renderedRow/Col，无 API 变更。

## fix(tui): Markdown 保留下划线标识符

**背景**：LLM 输出、文件名与错误信息中的 snake_case 标识符会被渲染成 snakecasename（两侧下划线被当成斜体标记吃掉）。

**根因**：renderInline 的下划线斜体正则允许跨越空格配对，provider_call ... provider_stream 中的两个下划线被配成一对斜体，两个下划线同时被删除。

**改动清单**：
- 单/双下划线强调增加 \b 词边界约束（CommonMark：词内下划线不产生强调）
- 新增 TestRenderInlineKeepsIntrawordUnderscores：snake_case_name / my_file.go / a_b_c / provider_call... 原样保留；_强调_、中文_强调_中文、__strong__ 仍生效；__init__ 按 CommonMark 渲染为粗体

**验证**：go test -race ./...、golangci-lint run ./... 通过；本地 mock SSE 实测回复 “标识符 snake_case_name 与 my_file.go 保持原样” 渲染无损。

**影响**：标识符与路径不再被破坏；合法下划线强调保持可用。

## fix(tui): 快捷键帮助改由 F1 触发，修正 footer 提示

**背景**：footer 宣称 “? help”，但按 ? 只会输入字符；旧的 case "question" 永远匹配不到真实按键名（ParseKeys 对可打印字符返回字面量）。

**为什么不用 ?**：焦点在编辑器上，TUI 先把按键交给编辑器（插入字符），再广播给 chatLayout；布局收到时编辑器已非空，无法可靠判断“按键前是否为空”。全局拦截 ? 会破坏正常问号输入。

**改动清单**：
- 帮助快捷键改为 F1（编辑器不消费，广播路径可靠）
- footer 提示由 “? help” 改为 “F1 help”
- 移除死的 question 分支与相关测试；新增 F1 打开帮助、? 保持可输入的用例

**验证**：go test -race ./...、golangci-lint run ./... 通过；tmux 实测 F1 打开 Keybindings，输入 “why?” 得到 4 个字符且 footer 显示 F1 help。

**影响**：帮助入口与提示一致；不再劫持问号输入。
