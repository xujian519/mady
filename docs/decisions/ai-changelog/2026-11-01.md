## fix(domains/teams): 修复团队调度公平性：单成员不再独占全部任务

**背景**：domains/teams 的 TestThreeAgentsCompleteTasksWithPersistedState 在 CI 上偶发失败（成员上下文未持久化），阻塞多个 dependabot PR 合并。根因是 Team.work 原为贪心循环：单个成员在一轮 dispatchRound 内可连续认领并执行多个任务，当 GOMAXPROCS=1（单线程调度）或任务执行极快时，首个被调度的成员会独占全部任务，其余成员无机会执行，会话状态未持久化。

**改动清单**：
- domains/teams/scheduler.go: Team.work 改为每轮至多认领并执行一个任务，由 RunUntilIdle 的外层循环反复重调度所有空闲成员，保证多成员公平参与，避免单成员独占。

**验证**：GOMAXPROCS=1 go test -count=100 ./domains/teams/ 全部通过；go test -race -count=20 ./domains/teams/ 全部通过；go build ./... 与 go vet ./domains/teams/ 通过。

**影响**：团队调度从贪心改为按轮公平分发，吞吐量略有下降（每轮需重调度），但保证成员参与公平性。domains/teams 当前仅被测试使用，无生产调用方。

## fix(tools/piagent): 适配 sky-valley/pi v1.4 API 变更

**背景**：PR #80 将 sky-valley/pi 从 0.85.21 升级到 1.4.28，coding 包 API 有破坏性变更，导致 tools/piagent 编译失败与测试不通过。

**改动清单**：
- tools/piagent/session.go: coding.NewSession 改为返回 (*Session, error)，新增错误处理；移除 SessionOptions.APIKey 字段（认证改由全局运行时从环境变量解析）；DefaultCompactionSettings 从变量改为函数调用 DefaultCompactionSettings()；默认模型从 deepseek-v4-flash 改为 deepseek-flash（pi 目录已移除前者）。
- tools/piagent/session_test.go: providers.FauxResponseStep 首参从 ai.Context 改为 ai.TranscriptContext；测试模型改为 deepseek-flash。

**验证**：go build ./tools/piagent/... 通过；go test ./tools/piagent/... 全部通过。

**影响**：piagent 子会话的 API Key 不再显式传入，依赖 pi 运行时从环境变量解析，行为与原 resolveAPIKey 一致（均读 API_KEY / DEEPSEEK_API_KEY 等）。
