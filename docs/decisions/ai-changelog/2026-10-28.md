# 2026-10-28

## fix(browser): 迁移至 chromedp 0.21 泛型 Action API

**背景**：dependabot 将 chromedp 0.16.0 升至 0.21.0，上游改为泛型 `Action[T]` API，移除 `ActionFunc`、`ByQuery`、`NewRemoteAllocator`、`ListenTarget` 及命令式 `.Do(ctx)`，导致 lint/test/desktop/example/integration 全部构建失败。

**改动清单**：
- allocator：`NewRemoteAllocator` → `remote.NewAllocator`
- 动作：多参 `Run` → `Do`；`ActionFunc` → `Func`；`ByQuery`/`BySearch` → `CSS`/`Search`
- 取值动作：`Title`/`Location`/`CaptureScreenshot`/`Evaluate` 改为泛型返回值 + 单动作 `Run`
- 事件：`ListenTarget` → `cdp.Events` 迭代器
- 直接协议命令：`page.X().Do(ctx)` → `chromedp.Call` / `cdp.Call`

**验证**：`go build ./...`、`go vet ./...`、`golangci-lint run ./...`（0 issue）、`go test ./tools/... ./domains/doctmpl/...` 全部通过。

**影响**：对外行为保持一致；录制器改用 cdproto 已解码的帧字节；停止录屏使用 `context.WithoutCancel` 保证清理命令可达。

## feat(pkg): 新增 pkg/indexasset 领域索引资产格式与 fail-closed 约定

**背景**：三域引入的 W0 基座要求法条、费用、日历等手工转录资产共用一套字段规则。若各模块自行解析，「有条文、无来源仍被判为已核验」这类 fail-open 状态在加载期无法拦截，法律结论会建立在无出处的文本上。

**改动清单**：
- 新增 `pkg/indexasset`：YAML 根映射解析、严格字段读取器（字符串/日期/计数/布尔/枚举/主题词/条目录）、`RequireKnownFields` 未知字段拒绝、来源记录 `sourceDoc`+`verifiedOn` 的全有或全无校验、`ReadArticleEntries` 重复条号拒绝。
- 兼容 yaml.v3 差异：未加引号的 `2026-09-26` 会被解析为 `time.Time`，读取器同时接受字符串与时间戳并统一为 `YYYY-MM-DD`。
- 新增 `docs/design/index-asset-format.md`：随包资产（模块内 embed）与外置资产（$MADY_HOME/根 data）的分发判据、目录布局、字段规则、来源三态语义。
- 新增 `docs/design/fail-closed-matrix.md`：11 条拒绝语义（法条未转录/无索引/越界、费用未转录、日历缺年份、出件断言、交付件不一致等）与允许降级清单。
- 新增 `scripts/asset-fingerprint` 与 `data/ASSETS.sha256`：转录类事实索引的 SHA-256 漂移校验，白名单只含 `data/law`、`pkg/lawcite/data`、`domains/fees/data`、`domains/deadline/data`。
- 资产格式移植自 deepseek-harness `packages/patent/patent-index-asset`，按 Go 习惯改为错误工厂 + `*indexasset.Error`。

**验证**：`go test -race ./pkg/indexasset/...` 通过（语句覆盖率 95.5%）、`go vet` 与 `go build ./pkg/... ./domains/...` 通过、指纹脚本生成/校验/篡改检测/幂等 4 项自测通过、`scripts/check-doc-consistency.py` 通过。

**影响**：新增纯库，无既有调用方。`data/ASSETS.sha256` 当前为空清单，W1 落位法条资产后自动填充；指纹脚本白名单不含规则包与模板，避免手写资产变更制造无效告警。

## feat(pkg): 法条核验接入随包索引并新增 law_verify 工具

**背景**：此前的引用核验只有条号存在性（静态主题词表）与 S2 wiki 索引，无法回答「条文原文是什么、依据哪份官方文书、何时核验」。引入随包法条索引后，核验结论可以区分「已核验」与「条号存在但条文未转录」，避免把只有主题词的条目报成已核验。

**改动清单**：
- `pkg/lawcite/index.go`：随包索引加载（embed 专利法 37 条、实施条例 45 条）与五值 `Resolve`（Verified / ExistOnly / OutOfRange / NarrowingMismatch / Unverified）；越界只在条数上限已核验时成立。
- `pkg/lawcite/lawcite.go`：新增 `ParseStatute`，按简称、全称与常用别名识别法律。
- `guardrails/citation_index.go`：`IndexCitationSource` 以索引优先、静态表回退；主题词合并去重；无索引法律一律返回未核验。
- `domains/lawverify/tool.go`：新增 `law_verify` 工具，支持从文本抽取引用或按 law+article 直接核验，输出条文、来源、核验日期与计数摘要。
- `bootstrap/setup_assembly.go`：装配顺序改为随包索引 > S1 静态表 > S2 wiki 索引。
- 资产落位 `pkg/lawcite/data/law/` 并更新 `data/ASSETS.sha256`。

**验证**：`go test ./pkg/lawcite/... ./guardrails/ ./domains/lawverify/... ./bootstrap/...` 全部通过；专利法已转录 37 条逐条判 Verified、其余 45 条判 ExistOnly、第 83 条判 OutOfRange、第 22 条第 6 款判 NarrowingMismatch；商标法因无随包索引判未核验。

**影响**：护栏主题词来源更权威，但结论口径未放宽——无条文的法律仍不可判为已核验。`law_verify` 为只读工具，不引用外部网络。

## feat(pkg): 并入 7,910 部法规条号骨架，仅用于存在性判定

**背景**：专利与法律结论常引用专利法族之外的法规（民法典、刑法、民诉法等），此前这些引用一律判未核验。民商事与诉讼文书写作需要的是一句「这条法规有没有这一条」，而不是条文原文；因此并入条号骨架，但严格限制其结论强度。

**改动清单**：
- `scripts/lawskeleton`：把逐部法规的条号索引 YAML 合并为单个紧凑索引，只保留存在性判定所需字段（名称、全称、修订、条数上限、是否带条文转录）；7,910 部法规未压缩约 1.8 MB，gzip 后约 190 KB。
- `data/law/skeleton/index.json.gz`：合并产物；读取方按 gzip 魔数自动识别，来源说明为 deepseek-harness legal-law assets，不含机器路径。
- `pkg/lawcite/skeleton.go`：骨架加载与查询；法律名按书名号、空白与「中华人民共和国」前缀归一化；`Resolve` 只返回 `ExistOnly` 或 `Unverified`，条数上限因无核验日期一律按未核验处理。
- `domains/lawverify/tool.go`：核验顺序改为精校索引 → 条号骨架 → 未核验，输出增加 `source` 字段（index/skeleton/none）；无法识别的法律名不再直接报错，交由骨架判定。
- `domains/lawverify/extension.go` + `domains/assemble.go`：工具挂入专利与法律域共享装配。
- `data/ASSETS.sha256` 纳入骨架索引。

**验证**：`go test ./pkg/lawcite/... ./domains/lawverify/... ./guardrails/ ./bootstrap/...` 通过。真实骨架加载 7,910 部、抽样 50 部第 1 条均判 `ExistOnly`；专利法第 22 条仍判 `Verified`（精校优先）；商标法在骨架中标记带条文转录，仍只判 `ExistOnly`；超出骨架上限判 `Unverified` 并说明上限未核验。

**影响**：引用覆盖面显著扩大，但结论强度不变——骨架不提供条文、不产生 Verified。工具新增 `source` 字段便于区分结论来源；专利法族结论仍以精校索引为准。

## feat(domains): 新增 patent_fees 官费测算，金额未转录或缺输入即拒算

**背景**：官费咨询此前只能查外部法律状态，不能在本地按费种计价。费用索引的实际状态是：19 个费种中 5 项金额未转录（说明书超页附加费、三类专利的年费顶层、延长期限费），年费按分档给出（发明 1–20 年度、实用新型与外观 1–10 年度）。因此计价必须区分「该缴什么」与「能不能给出金额」。

**改动清单**：
- `domains/fees/table.go`：严格加载费用索引（费种、计数基准、减缴、年费分档、滞纳金），未知枚举与重复 id 报错。
- `domains/fees/compute.go`：按收费阶段与专利类型筛选；六种计数基准；减缴按 85%/70% 且受「已备案」与「减缴覆盖年度」约束；年费按分档，超窗滞纳金提示专利权终止。
- `domains/fees/money.go`：金额以分为整数运算，百分比四舍五入到分。
- `domains/fees/tool.go` + `extension.go`：新增只读工具 `patent_fees`，挂入专利域装配。
- `domains/fees/data/cn-fees.yaml`：随包费用索引，纳入 `data/ASSETS.sha256`。

**验证**：`go test ./domains/fees/` 13 个用例通过——发明申请合计 950、实用新型申请 500、个人减缴已备案申请费 900→135、年费 1/4/10 年度合计 6100、滞纳金 2 个月 90、超 6 个月窗口不给金额、第 21 年度超出分档不给金额、说明书附加费未转录导致合计扣留、缺计数输入进入 pending。

**影响**：计价口径比「只统计已有金额」更严——存在等待输入的费种时也不给合计，避免部分合计被读成应缴额；金额未转录或未核验一律拒算，与 fail-closed 判定表 FC-5/FC-6 一致。

## feat(domains): 期限增强：推定送达、节假日顺延与申请费择先适用

**背景**：既有期限计算只从申请日推算法定年限，无法处理通知书送达后的指定期限，也没有节假日顺延。2026-10-14 曾发现 15 件在办案件因「申请费缴纳期限」按较晚者计算而各晚 44–48 天，本次把「择先适用」作为硬口径实现。

**改动清单**：
- `domains/deadline/date.go`：日期运算以 UTC 零点归一；按月加减时目标月无该日则取月末（细则第五条），1999-12-31 加两个月为 2000-02-29。
- `domains/deadline/workcalendar.go`：随包节假日与调休上班日历；调休上班日优先于周末判定；年份未覆盖返回 `CalendarCoverageError`，不按「非休假日」猜测。
- `domains/deadline/delivery.go`：四种送达方式的送达日判定——电子送达以进入系统日或发文日为准（不加 15 日）、邮寄以实际收到日或发文日 +15 日推定、直接送交按交付日、公告送达加 1 个月。
- `domains/deadline/designated.go`：五类通知书指定期限（驳回 3 个月、一通实审 4 个月/初审 2 个月、后续 OA 2 个月、复审通知 1 个月、无效转送 1 个月），通知书自身指定月数优先；届满日按细则第五条顺延。
- `domains/deadline/designated.go`：`ApplicationFeeWindow` 实现申请费缴纳期限的「择先适用」——「自申请日起 2 个月」与「自收到受理通知书起 15 日」各自顺延后取较早届满者。
- `domains/deadline/data/cn-holidays.yaml`（2025–2026，含国务院文号）纳入资产指纹。

**验证**：`go test ./domains/deadline/` 全部通过——月末对齐 5 例、节假日/调休 9 例、顺延 5 例、送达 7 例 + 5 个缺输入反例、通知书期限 4 例 + 指定月数覆盖、择先适用 3 种情形。其中 03-06 + 1 个月落在清明假期时正确顺延到 04-07。

**影响**：新增能力目前是库 API，未改动既有 `calculate_patent_deadlines` 工具的参数模型；工具接线留到答复链路（W2）。与 dsh 的差异：dsh 只算「申请日起 2 个月」，本实现补上择先适用，避免以较晚届满日提示。

## feat(domains): 新增规则输出门禁与结构门禁，批 A 接入 4 条确定性规则

**背景**：此前规则的唯一消费方式是模型主动调用 query_rules，没有运行时强制。deepseek-harness 的 patent-rule 用规则门禁在工具执行前后拦截，本次移植其机制并接入第一批确定性规则。

**改动清单**：
- `domains/rules/evaluate_gate.go`：新增两个确定性检查类型——`keyword_blocklist`（支持否定语境与成对引号豁免，未闭合引号不豁免）与 `structural_analysis`（requiresAll + minConfidence）。
- `domains/rules/gate.go`：`OutputGate` 在 AfterToolExecution 对结果追加合规提示或「不可作为交付依据」标注（改写 ForLLM，幂等）；`StructuralGate` 在 BeforeToolExecution 对交付工具入参跑 block 级规则并拒绝调用；`ValidateGateRules` 拒绝非确定性检查类型。
- `domains/rules/gate_embed.go` + `data/rules/gate-batch-a.yaml`：批 A 规则随包分发，不依赖 `$MADY_HOME`，避免门禁因部署目录缺失静默失效。
- 批 A 首批 4 条：PAT-RISK-001（风险结论免责）、PAT-APPROVAL-001（结论人工审批）、PAT-ABS-001（回避绝对化）、CON-COMP-0106（结论须有法律与事实依据）。
- `domains/assemble.go`：专利与法律域共享装配注册 OutputGate；结构规则的误用防线——OutputGate 显式跳过 `structural_analysis`（该类型只对交付制品判定，对任意工具结果全文必然报缺要素）。

**验证**：`go test ./domains/rules/` 通过，覆盖否定语境、成对/未闭合引号、结构要素齐缺、门禁按 action 判定、whenArgs 精确匹配、未知类型拒绝。**反向验证**：把 keyword_blocklist 的判定临时改为恒通过，OutputGate 与 StructuralGate 两个测试变红；还原后恢复绿色。

**影响与剩余**：门禁机制已完成；批 A 的 44 条规则中已转换 4 条，其余 block/结构性规则与批 B 的 warn/log 规则待续。StructuralGate 的 entries 需在 W2 交付工具就绪后配置。另发现既有 `data/rules/inventiveness.yaml` 的 `principles` 为映射，无法被 `Check` 的字符串数组字段解析——该目录不在生产加载路径（生产读 `$MADY_HOME/knowledge/rules`），属潜伏缺陷，本轮未修。
