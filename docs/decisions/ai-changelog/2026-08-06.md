## feat(domains/workflows/patent): OA 答复支持多驳回类型策略生成 + 权利要求区间展开修复

**背景**：OA 通知书常同时引用多种驳回理由（如权利要求1-3新颖性、权利要求4创造性、权利要求5不清楚），原解析器只取第一个匹配类型生成单一策略，且'权利要求1-3'区间写法无法展开（只提取到 1）。

**改动清单**：
- rules/oa_parser.go：新增 DetectOaRejectionTypes（多类型检测，按文本出现位置排序去重）；DetectOaRejectionType 改为返回第一个（向后兼容）；ParsedOfficeAction 新增 RejectionTypes 字段；区间正则扩展支持'权利要求1-3'/'权利要求1至3'写法；收紧 OaScope 关键词（移除宽泛的'保护范围'，避免误占'保护范围不清楚'）
- workflows/patent：ParsedOfficeAction 增加 RejectionTypes；classify_rejection 按每个驳回类型生成策略与模板（新增 OAStateRejectionTypes/OAStateStrategies/OAStateTemplates state key）；analyze_claims 修改对照表增加'驳回类型'列、策略建议按类型分段；draft_response 意见陈述逐类型编号（一、二、三…）+ 单一结论；rule_retrieval 按类型逐个检索并合并去重，部分失败降级不阻断
- 测试：新增多类型检测/区间展开/混合管线等 10+ 用例（rules + workflows/patent）

**验证**：go test -race ./domains/workflows/patent/... ./domains/rules/... ./domains/casemgmt/... 全过；go build ./... 通过；CLI 实测三类型混合 OA 正确生成三段意见陈述与按类型修改对照表

**影响**：纯增强，向后兼容（单值 RejectionType/OAStateRejectionType 保留）；case_extractor 单值案件元数据不受影响
