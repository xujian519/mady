## refactor(agentcore/permission): M43 敏感路径确认：rule.go 解析失败 fail-open 边界

**背景**：终审报告 §五 P1-1 唯一剩余静默吞错点。`agentcore/permission/rule.go` 的 `extractMatchValue` 在 `json.Unmarshal` 失败时返回空串，上层 `Rule.Matches` 将其视为「不匹配」。`agentcore/permission/` 属敏感路径前缀，需人工确认该降级是否应改为 fail-closed。

**取证结论**：当前无可利用缺陷，属理论风险——`Rule.Matches` 在 `Specifier == ""` 时直接返回 true、不解析 args；生产策略（`ProjectAgentPolicy`、`DenyDangerousToolsExtension`、`patent.go` 的 `MonotonicDenyFns`）均为工具粒度，全仓非测试代码无 `Specifier:` 赋值与 `ParseRule` 调用。

**改动清单**：
- `agentcore/permission/rule.go`：仅在 `extractMatchValue` 的 `json.Unmarshal` 错误分支补中文意图注释，说明「交给工具自身参数校验兜底」及「引入带 specifier 的 Deny/MonotonicDeny 时需评估 fail-closed」的边界；零行为变更、零删除

**边界（登记）**：若未来配置带 specifier 的 `Deny`/`MonotonicDeny`（如 `Edit(secrets/**)`），畸形 args 会使规则不命中而落到 Mode（多为 Allow），形成 fail-open；届时需改为 fail-closed。

**验证**：`gofmt` 干净；`go build ./... && go vet ./...` 全绿；`golangci-lint run ./...` 0 issues；`go test -race ./...` 128 包通过（唯一失败为预存 `knowledge/sqlite TestSearchLaws`）；`make check-arch doc-check verify-layers debt-check` 通过；`scan_go_smells.py` 静默吞错 1 → 0。

**影响**：仅新增注释，零行为变更。敏感路径变更经用户人工确认后，以 `SKIP=check-sensitive-paths` 放行提交（gate 对 AI 参与 + 敏感路径组合的既定保护不变）。
