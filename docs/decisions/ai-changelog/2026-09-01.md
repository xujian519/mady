## fix(agentcore): EventBus unregister 同步等待 in-flight 回调（修复 server 流式 SSE 数据竞争）

**背景**：CI（PR #49/#50 的 ubuntu race 测试）发现 TestServerStreamChatEmitsMCPEvents 数据竞争——handleStreamChat 的事件回调经 EventBus dispatch goroutine 异步写 httptest ResponseRecorder，而 unregister() 仅从 map 移除注册、不等待 in-flight 回调结束；handler 返回后 dispatch goroutine 仍可能写 sink。生产环境同等危险：HTTP handler 返回后 ResponseWriter 会被 net/http 复用，迟到的 SSE 写会损坏后续响应。otel 1.46 的调度时序变化使该既有竞态在 CI 暴露。

**改动清单**：
- agentcore/event.go：On/OnAll 返回的 unregister 闭包在移除注册后调用 Drain()，利用 dispatch 串行 + drain sentinel 机制保证返回时 in-flight 回调已结束；补充 unregister 同步语义的文档注释

**验证**：`go test -race ./agentcore/ ./server/ -count=2` 全绿；`make verify` 全绿。

**影响**：unregister 变为同步等待（含 drainTimeout 5s 上限保护，closed bus 时立即返回）；消除 handler 返回后写 sink 的竞态窗口。
