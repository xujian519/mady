背景：TUI 智能体输出长期不完整，深度审查定位三个 tui/chat 层根因。S5：onAgentEnd 忽略 AgentEndChatEvent.Output 不做最终对账，丢一个 delta 就永久丢文字。S2：applyDeltaLocked 的 deltaHistory 对消息全生命周期精确去重，长输出中重复的 markdown 结构 chunk（```、**、---）第二次起被静默吞。S3：08-04 引入的 look-behind overlap 剥离无条件触发，中文叠字跨 chunk 必丢字（'让我想想'+'想办法'→'让我想想办法'）。改动：1) chat_history.go 新增 FinalizeWithOutput(id, output)，output 非空且不一致时以全文为准替换 Text（thinking 段不动）；finalizeStreamLocked 带 finalOutput 参数，onAgentEnd 传 ev.Output，其余 7 个中断路径传空。2) deltaHistory map 删除改 lastDelta，仅抑制'连续、同 kind、多 rune 完全相同'的 delta（防重放），非连续重复一律保留。3) 删除 overlap 剥离分支与 longestOverlapRuneCount，回到朴素 append，最终正确性由 FinalizeWithOutput 对账兜底。测试：改写 3 个固化错误预期的旧测试，新增 6 个回归（重复 code fence chunk、跨 chunk 叠字、丢 delta 后对账、空 Output、thinking 保留）。验证：cd tui && gofmt/vet/build/test -race 全绿。

## fix(chatcompat): SSE 流式静默截断修复：1MB scanner + Err 检查 + 流式独立超时 + error 终态 delta

背景：provider/chatcompat SSE 读取层三个叠加缺陷，全部表现为'输出戛然而止且无报错'，历史上从未被审：1) bufio.Scanner 默认 64KB 上限，超长 SSE 行静默截断且无 scanner.Err() 检查；2) http.Client 5min 整体超时覆盖整个流式交换，长推理被杀；3) JSON 解析失败与中流 error 载荷静默跳过。改动：1) Provider 新增 streamClient（clone DefaultTransport，ResponseHeaderTimeout 60s，整体 Timeout=0 靠 ctx 取消），非流式保留 5min；responses.go 对称修复。2) scanner.Buffer 64KB→1MB；循环结束检查 scanner.Err() 与 EOF 无 [DONE]，异常时发终态 StreamDelta{FinishReason:'error'}（ctx 取消不误报）。3) 解析失败与 error 载荷 slog.Warn。4) agentcore/agent_provider.go buildResponse 对 finishReason 空/'error' 各加 slog.Warn。测试：新增 6 个 httptest SSE 用例（200KB 大行、断连无 DONE、中流 error 载荷、坏行跳过、client 超时配置断言、慢速流不受整体超时限制）。验证：go build/vet/test -race（agentcore + provider）全绿，golangci-lint 0 issues。

## feat(agentcore): 输出异常结束透传 TUI 可见：AgentEndEvent 带 FinishReason，截断/中断出用户提示

背景：finish_reason=length（打满 max_tokens）且无 tool call 时 agent_run.go 直接 StatusFinished，不发事件、不续写、TUI 无任何提示——长回答被 8192 截断用户毫无感知，是'始终无法完整输出'的系统性根因之一；chatcompat 的 error 终态同样只落 slog。改动：1) agentcore/event_types.go AgentEndEvent 新增 FinishReason 字段（通用设计，覆盖 length/error，stop/空不提示）；agent_run.go runInnerLoop 返回 finishReason，runLoop 构造 AgentEndEvent 时填充（earlyExit/handoff/interrupt 路径为空）。2) tui/agentadapter 透传至 AgentEndChatEvent。3) tui/chat onAgentEnd 在 finalize 后按 FinishReason 用既有 PrintSystem 追加提示：length→'输出达到长度上限（max_tokens），内容可能不完整。可发送"继续"让智能体接着输出。'；error→'连接异常中断，输出可能不完整。可重新发送或让智能体重试。'（对照 tone-style-guide 禁用词表）。空 finishReason 不归一化为异常（非流式 stub 合法不填，避免误报）。测试：agentcore 3 例（length/error/stop）+ tui/chat 3 例（提示出现/不出现/正文不受干扰）。验证：根模块 + tui + desktop build/vet/test -race 全绿，golangci-lint 0 issues。
