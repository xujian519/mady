## 摘要

`mcp/` 是 MCP（Model Context Protocol）客户端层，承担 stdio/HTTP/SSE 三种传输、`.mcp.json` 配置发现与信任校验、子进程生命周期管理。整体安全姿态**良好**——无 shell 注入、无 TLS 弱化、fail-closed、密钥 0600 持久化、子进程树清理完整。三处可改进点集中在 **C7 信任门的时序窗口与覆盖面**：

1. **⚠️ 信任门存在 TOCTOU 时序窗口（窗口 B）**。`config_discovery.go:131-145` 三步串行：`isOwnedByCurrentUser` → `isConfigTrusted`（哈希比对）→ `LoadMCPConfig`（实际加载）。信任校验读取的是**旧内容**（哈希匹配信任库），而 `LoadMCPConfig` 读取的是**新内容**——两步之间若攻击者改写文件（如可写组权限、符号链接替换），可在通过信任门后注入恶意 command。严重度 M：需精确时序 + 写权限双前提。
2. **⚠️ `isOwnedByCurrentUser` 零直接测试**。该函数是 C7 投毒防线的**第一道闸**（共享目录投毒防护），但在 `mcp/` 测试套件中 grep `TestIsOwnedBy*` 零命中。Unix/Windows 两份实现均无单测覆盖，回归无护栏。
3. **ℹ️ 三类显式用户意图配置源不走信任门**。`$MCP_CONFIG` / `~/.mady/mcp.json` / `~/.claude.json` 在 `config_discovery.go:124-145` 仅 `$PWD/.mcp.json`（cwdConfigPath）走 owner+trust 校验，其余路径直接 `LoadMCPConfig`。这是**有意设计**（注释 123-126 明示"显式用户意图来源"），符合"克制"理念，但需在文档明示边界。

正面发现（已验证合规）：无 `exec.Command("sh","-c",...)` 拼接（command+args 数组传递，**无 shell 注入面**）；`http.Server` 未自定义 `TLSConfig` 弱化默认；`config_trust.go` 信任库 `0600` 持久化；`config_discovery.go:140` 未信任时返回带引导文案的 warning（"run `mady trust-mcp`"），符合 tone-style-guide 的"拒绝类文案提供替代帮助"；子进程 `cmd.Process.Kill` + `cmd.Wait` 完整。
