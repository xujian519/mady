# 领域能力 fail-closed 判定表

> 用途：统一「缺数据 / 数据未核验 / 外部工具不可用」时的行为，避免静默降级。
> 配套：`docs/design/index-asset-format.md`、`docs/plans/dsh-domain-import-tasks.md`。
> 原则：**拒绝必须显式、可定位、可测试**；「降级」只用于仍能给出可信结果的场景。

## 1. 四类拒绝语义

| # | 场景 | 触发条件 | 行为 | 用户可见表达 | 对应测试 |
|---|---|---|---|---|---|
| FC-1 | 法条未转录 | 条目命中骨架但 `text == nil` | 返回 `ExistOnly`，不得判 `Valid` | 「条号存在，条文未转录，不能据此确认内容」 | `TestReadArticleEntries`、W1 的法条负控制 |
| FC-2 | 法条无索引 | 该法族未收录 | 返回 `Unverified`（映射到 `Unknown`） | 「未收录该法条，未做核验」 | W1 `law_verify` 用例 |
| FC-3 | 条号越界 | `article > maxArticle` | 返回 `OutOfRange`（映射到 `Invalid`） | 「条号超出该法现行条数（上限 N）」 | W1 条号漂移回归 |
| FC-4 | 来源不完整 | `text` 有值但缺 `sourceDoc`/`verifiedOn` | **资产加载失败**，整份索引不可用 | 启动期错误，指出文件与条号 | `TestCheckRecordedSource` |
| FC-5 | 费用金额未转录 | 条目 `amount == nil` | 不给出合计；该条目列入 `Refused` | 「该项官费未转录，不能给出合计」 | W1 费用金标用例 |
| FC-6 | 费用基准不支持 | 如按页两档、按次延期 | 拒绝该项，说明格式表达不了 | 「该项按两档计价，本工具不能给出可靠金额」 | W1 费用用例 |
| FC-7 | 日历缺年份 | `cn-holidays.yaml` 无该年度 | 报错，不按"非休假日"处理 | 「缺少 YYYY 年节假日安排，无法判断届满日顺延」 | W1 期限用例 |
| FC-8 | 出件断言失败 | 节数/编号/禁用词/字号不符 | 不出件，删除中间产物 | 「出件被拒绝：<具体断言>」 | W2 出件反例 |
| FC-9 | 交付件不一致 | 主路径与交付副本字节不同，或产物早于输入 | `VerifyDeliverable` 判失败 | 「主路径仍是旧稿 / 出件早于改稿」 | W2 交付件用例 |
| FC-10 | 外部渲染器缺失 | `freecadcmd`/`soffice` 不存在 | 该能力返回 `setup_required` 或走降级通道 | 给出安装指引或替代通道 | `scripts/check-domain-deps` |
| FC-11 | 规则类型未知 | 规则 YAML 的 `check.type` 不在支持集 | 加载期报错，不跳过该规则 | 「规则 <id> 的检查类型 <type> 未实现」 | W1 规则适配用例 |

## 2. 允许的降级（不属于 fail-closed）

| 场景 | 降级方式 | 前提 |
|---|---|---|
| 知识库 SQLite 不可用 | 内存检索 | 降级结果标注「未使用全文索引，召回可能不完整」 |
| Chrome 不可用（HTML→PDF） | 纯 Go gopdf 渲染 | 中文字体缺失时明确报错，不产出乱码 PDF |
| LibreOffice 不可用（Office→PDF） | `pandoc + typst` | 抽查版式保真度；两者皆缺时拒绝 |
| 法规骨架未收录 | 不做条号存在性判断，直接 `Unverified` | 不得据此推断「不存在」 |

**判定标准**：降级后的结论是否仍可用于业务判断？可以 → 允许降级并标注；
不可以 → 必须拒绝。

## 3. 状态值与对外措辞

| 内部状态 | 护栏五值 | 报告措辞 |
|---|---|---|
| `Verified` | `Valid` | 「已核验（来源：…，核验日期：…）」 |
| `ExistOnly` | `Unverifiable` | 「条号存在，条文未转录」 |
| `OutOfRange` | `Invalid` | 「条号超出有效范围」 |
| `Unverified` | `Unknown` | 「未收录，未核验」 |

禁止把 `ExistOnly` 简写为「已核验」或「有效」——这是本表存在的首要原因。

## 4. 实现要求

1. 每个 FC 条目在代码中有对应的哨兵错误或状态值，不靠字符串匹配判断。
2. 错误消息必须包含定位信息：文件、条号/条目 id、字段名。
3. 修 bug 时必须先补一个「反例测试」证明当前会被拦截，再改实现。
4. CI 中的 `scripts/check-domain-deps` 只用于环境可用性，不替代运行时拒绝逻辑。
